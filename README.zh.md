# dsh-remote-access

给 [DeepSeek Harness](https://www.npmjs.com/package/@deepseek-ai/dsh) 加上远程访问：用手机或其它设备打开 Harness 的 Web UI，并在一页设置里管理进入它的每一道门。

[English](README.md) | 中文

## 它做什么

Harness 本身已经具备难的那一半：浏览器界面、每次启动生成的一次性令牌（换取签名 Cookie）、Host/Origin 信任栅栏，以及"只绑定一个具体网卡地址"的监听能力。它缺的是外面那一圈——"只给本机和同一 Wi-Fi"与"给公网"之间的切换、别的设备用什么凭据进来、哪些凭据还活着、以及怎么收回来。

本插件就是这一圈：

| 面板区块 | 提供什么 |
|---|---|
| **访问模式** | 顶部双按钮开关：**局域网** 与 **公网**，按当前绑定自动判定。开关只是**预览**：点 **启用此模式** 才真正应用（立即生效——到新地址重新打开面板；重启 dsh 仍然建议做）。只渲染所预览模式的配置。 |
| **入口链接** | 设备要打开的那个带令牌网址，二维码收在 **显示二维码** 开关后面。**局域网**模式下标记为 *临时：随进程失效*；平台的启动令牌本来也是每次进程生成的。 |
| **一次性配对码** | 8 位字符、10 分钟、只能用一次，并附一个把码写进网址里的二维码——给够不到这块屏幕的设备用。 |
| **授权设备** | 授权依据列表：本机签发出去的每一条凭据（来源、临时/长期、创建时间、最近使用 + 客户端 IP、明确到期时间、状态），每条都能单独撤销、改名、改有效期；每台有效设备还有 **获取链接**，现场签发一条新的 15 分钟一次性链接。 |
| **Cloudflare 隧道** | 一颗显眼的 **启动隧道** 按钮、子进程状态与最近输出，以及隧道对外服务的域名。 |
| **边缘认证** | 该域名前面是否挂着 Cloudflare Access 应用——未启用时状态行是警示色。 |
| **高级** | Cloudflare 配置（环境检测、引导浏览器登录、API Token、清理）、访问密钥、恢复密码，以及手机端布局微调。 |
| **配置 skill** | 安装插件即安装 `dsh-remote-access`，可在新对话里让它带着走完整套配置。 |

能让设备进来的凭据有四类，四类都会变成同一个 **授权设备** 列表里的一行：**入口链接**、**一次性配对码**、**访问密钥**，以及可选的**密码**。它们的真实参数见[四种凭据来源](#四种凭据来源)。

## 它刻意不做什么

**它不另做一套手机界面。** 手机用的就是现有 Web UI：布局在 1024px 以下会自动把侧栏收成轨道，因此手机拿到的是可用的单列对话界面，且具备桌面的全部功能。这个选择有两个代价，必须说清楚：

- **设备拿到的是 owner 全权。** 因为就是同一个界面，它能做桌面能做的一切。边界来自平台 Cookie 与隧道身份，而不是被削减的功能集。
- **平台 Cookie 无法按设备撤销。** 平台不为浏览器 Cookie 保存设备维度状态，插件也无法给平台的 `/api` 路由加中间件。撤销 Cookie 只能一次全撤。按设备撤销只对本插件签发的凭据有效。

以下这些同样是它刻意选择或明确拒绝的：

- **它不能签发平台令牌。** 启动令牌属于正在运行的进程。这里的"临时令牌"是插件凭据，用来换一条平台入口链接，它不是平台令牌。
- **它从不滑动有效期。** 没有任何隐藏续期去延长任何凭据：面板显示什么，就什么时候到期。
- **它不强制 Cloudflare Access。** Access 是可选的；开启后它排在该域名上的一切之前——包括配对码页面与密码页面。
- **它不做局域网/隧道之间的自动切换。** 一个监听只能绑一个地址，而且请求到达时 DNS 早就答过了；面板改为如实显示实际走了哪条路。
- **它不从 `.env` 读取 `DSH_*`。** 这些变量必须在启动器环境里 export；任何 `DSH_*` 出现在 `.env` 里都会让启动直接抛错。

## 环境要求

- 一个带 `web` profile 的 DeepSeek Harness。本插件是**profile bundle**：只增加一个 host 行（`id: remote-access-panel`）和一个设置区块。
- `cloudflared`——只在需要公网访问时才要。面板会检测它、给出对应平台的安装命令，之后引导登录或 API Token 会把剩下的事做完。只走局域网则什么都不需要。
- 一个 DNS 由 Cloudflare 托管的域名——同样只在公网访问时才要。不需要公网服务器、不需要开放任何入站端口。
- Node 20+，且本插件**没有任何运行时依赖**（只用到 `node:crypto` 与平台自身的服务）。

## 安装

```sh
  # 从 GitHub 安装（pnpm 解析默认分支）
dsh plugin --profile web add github:mathangler/dsh-remote-access

  # 或从本地检出安装——开发本插件时用的就是这种
dsh plugin --profile web add /absolute/path/to/dsh-remote-access
```

`dsh plugin` 会把参数原样转发给 profile 目录里的 `pnpm`；凡是声明了 `dsh.bundle` 的依赖都会被追加进 `dsh.profile.bundles`。如果你的网络封了 git over HTTPS，就用本地检出那种写法。

然后：

1. **重启 Harness**——host 半（路由、受管的 cloudflared 子进程、配置 skill）在启动时加载。
2. 打开 **设置 → 远程访问**。这个区块就是全部界面。

安装的同时会装上**配置 skill**，所以在新的对话里让它"配置远程访问"，它会带着你把整套配置走完。

## 更新

```sh
dsh plugin --profile web add github:mathangler/dsh-remote-access   # 重新解析分支
dsh plugin --profile web update dsh-remote-access                  # 或更新该依赖
```

然后重启 Harness。**面板写过的所有东西都会保留**，因为它们在你的 profile patch 层，而不在包里：域名、隧道名、局域网绑定、对外广播地址、`trustedHosts` 条目、cloudflared 设置。凭据记录与 Cloudflare 机密在 Harness 凭据库里，同样保留。

## 卸载

```sh
dsh plugin --profile web remove dsh-remote-access
```

然后重启 Harness。包、它的行和设置区块都会消失；它托管的隧道也随之停止——那个子进程属于插件的 fiber。

以下内容是**故意留下的**，因为它们属于你：

| 内容 | 位置 | 怎么清理 |
|---|---|---|
| 凭据记录（`devices`、`devices-v2`、`access-keys`、`recovery`、`device-tokens`、`pair-codes`，都在 `dsh-remote-access/` 作用域下） | Harness 凭据库 | **卸载插件之前**先在面板里逐条撤销、删除，并移除恢复密码 |
| 面板写入的行配置（域名、隧道名、局域网绑定、广播地址） | 你的 profile `cordis.patch.yml` 里 `id: remote-access-panel` 那条 | 删掉该条 |
| 信任栅栏条目 | 同一文件的 `id: connection` → `trustedHosts` | 从列表里去掉该域名 |
| `~/.cloudflared/*`——隧道配置文件、连接器凭据文件与 `cert.pem` | 你的主目录（Windows 是 `%USERPROFILE%\.cloudflared`） | 删掉这些文件 |
| 本插件创建的 DNS 记录、隧道与 Access 应用 | Cloudflare | **卸载插件之前**先在 **高级 → Cloudflare 配置** 里点清理按钮，或到控制台自行删除 |
| 已保存的 Cloudflare API Token 与连接器令牌（`CLOUDFLARE_API_TOKEN`、`CLOUDFLARE_TUNNEL_TOKEN`） | Harness 凭据库 | 面板 → **清除已保存的 API Token**；连接器令牌由清理按钮移除 |

## 使用

### 选择模式

面板默认落在当前绑定所对应的模式：监听绑在本机某个非回环地址时是 **局域网**，绑在 `127.0.0.1` 时是 **公网**。顶部那个双按钮开关只是**预览**：它只决定显示哪一套配置，在你点 **启用此模式** 之前什么都不会写入（当预览的模式就是当前已启用的模式时，面板显示 *当前已启用*）。点下 **启用此模式** 后**立即生效**——监听会重新绑定，这个页面可能变空白或失联，请到新地址重新打开面板；**重启 dsh 仍然建议做**。启用局域网后，桌面端也必须改用新地址，因为绑定到某个具体字面量的监听不再响应 `127.0.0.1`。

### 局域网步骤

1. 选 **局域网**，在地址列表里挑一个地址——开关只是预览，此时还没有写入任何东西。
2. 点 **启用此模式**。它立即生效：监听重新绑定到该地址，而这个页面可能变空白或失联，请到新地址重新打开面板（`http://<地址>:3080`）。仍然建议重启 dsh。
3. 打开入口链接，或点 **显示二维码** 让设备扫码。它标着 **临时：随进程失效**。
4. 到此为止：这个模式下**没有设备管理**，因为平台的启动令牌随进程失效，插件也不会为它留长期记录。
5. 要退回去，点 **恢复回环绑定（127.0.0.1）**——页面可能再次变空白，到 `http://127.0.0.1:3080` 重新打开面板即可。

### 公网步骤

1. 选 **公网** 并点 **启用此模式**——监听回到 `127.0.0.1`；若这个页面变空白，就到 `127.0.0.1` 重新打开面板。
2. 在 **高级 → Cloudflare 配置** 里填设备要打开的域名（例如 `dsh-win.example.com`）和这台机器的隧道名（`dsh-win`），然后二选一建隧道：
   - **检测环境 → 开始浏览器登录 → 创建隧道并完成配置**，或
   - 粘贴 Cloudflare API Token → **一键自动配置**。
   两者都会发布 DNS 记录、写出 `~/.cloudflared/dsh-remote-access.yml`，并把域名写进平台信任栅栏。浏览器登录**必须从面板发起**：在终端里起的登录进程活不长，会在写出 `cert.pem` 之前被结束，结果就是"授权了却像什么都没发生"。
3. 点 Cloudflare 隧道卡片上那颗显眼的 **启动隧道** 按钮（卡片里唯一那颗填充色主按钮）。隧道作为 Harness 的子进程运行，插件停用或重启后即停止。
4. 配对一台设备：点入口链接上的 **显示二维码** 再扫，或生成一个配对码（见下节）。
5. 可选：创建 Access 应用，让 Cloudflare 在任何流量到达这台机器之前先要一次邮箱验证码。

入口链接的第一次访问会把本次进程的启动令牌换成平台 Cookie。它的二维码收在 **显示二维码** 开关后面。从二维码或别的 App 点开时，**第一次落地通常需要刷新一次**——平台的 Cookie 是 `SameSite=Strict`，跨站导航后的跳转不会带上它；把链接粘贴到地址栏则一次就能进。

如果面板给某条刚生成的链接打上 **loopback-only** 警示（*此链接只在本机有效*），说明它出不了这台电脑：要么在 **高级 → Cloudflare 配置** 里配好域名（公网模式），要么切到局域网模式。

### 用配对码或二维码添加设备

在 **公网** 模式下，面板的配对卡片会生成一个 **一次性配对码**：8 位字符，字母表不含 `0`、`O`、`1`、`I`、`L`。它 **10 分钟内有效**、**只能用一次**、有速率限制，且只能**从已授权会话生成**。面板会同时显示这个码和它的二维码；二维码里编码的是带上该码的网址，所以新设备扫码或手输都可以。

生成之前先选新设备记录拿到的**有效期**：*永不过期*、30 天、90 天、1 年，或自定义日期（未指定时主机默认 1 年）。之后那条记录会带着这个到期时间出现在 **授权设备** 里。

### 使用访问密钥

在 **高级 → 访问密钥** 里点 **创建访问密钥** 并起个名字。密钥形如 `dra_…`，**只显示一次**，本机只保存它的 sha256 指纹——请当场复制，需要新的就重置。设备拿它在 `POST /remote-access/token` 换取一条 **15 分钟、一次性**的入口链接：它把那个浏览器一次性地送进应用，并在使用的同时作废，无论它此前是否已经过期。

密钥可以逐条撤销（立即失效），也可以重置（旧密钥立刻作废，新密钥只显示一次）。

### 用密码恢复访问

在 **高级 → 恢复访问** 里设置一个至少 12 个字符的密码。校验走挑战-应答：host 下发一次性 nonce 与盐，浏览器用 PBKDF2-SHA256（600,000 次迭代）派生密钥，再对 nonce 做 HMAC 应答。**密码不过网。** 成功后 host 给回一条**最多 15 分钟**的一次性链接；页面关闭时再发一个尽力而为的 beacon 提前作废它。

没有设置密码时，恢复页**什么都不渲染**，公网表面也保持沉默：未认证访问域名只会看到平台原本那句 401，`/remote-access/unlock` 直接返回 404。

恢复顺序，按这个顺序试：

1. **设备记录**——配对过一次的设备带着一枚插件凭据，平台 Cookie 失效后它回来时会自动续上。要手动把链接交给一台有效设备，就在 **授权设备** 里对它点 **获取链接**：现场签发一条新的 15 分钟一次性链接，另有自己的 **显示二维码** 开关。
2. **访问密钥**——在 `POST /remote-access/token` 换一条新的一次性链接。
3. **密码**——打开 `https://<主机名>/remote-access/unlock`，应答挑战。
4. **回到电脑前**——三样都没有时，重新配对必须碰到这台机器。

## 配置

全部配置都在插件行的 `config` 里，面板会替你写入你自己的 profile patch 层（因此升级不会丢）：

```yaml
- insert:
    - id: remote-access-panel
      name: dsh-remote-access
      config:
        tunnelHost: dsh-win.example.com
        publicUrl: https://dsh-win.example.com
        lanHost: 10.0.161.47
        tunnelName: dsh-win
        accessEmail: you@example.com
        cloudflared:
          command: cloudflared
          args: ['tunnel', 'run', 'dsh-win']
        narrowEnhance: true
        deviceRetentionDays: 180
```

| 字段 | 含义 |
|---|---|
| `tunnelHost` | 隧道服务的域名（authority）。只有设置后，公网入口链接与二维码才会出现。 |
| `publicUrl` | 可选的对外公开根地址（Harness 打印的 URL 与 `DSH_WEB_URL`）。 |
| `lanHost` | 可选的局域网具体地址字面量。通配地址由平台本身拒绝。 |
| `tunnelName` | 自动配置创建或复用的隧道名（默认 `dsh-remote-access`；一台机器一个名字）。 |
| `accessEmail` | 可选的 Cloudflare Access 策略允许的邮箱。 |
| `cloudflared` | 可选：作为子进程管理的命令。不填就由你自己跑隧道。 |
| `narrowEnhance` | 是否在 1024px 以下应用手机端布局微调（默认 `true`）。 |
| `deviceRetentionDays` | 超过该天数未再出现的活动记录会被清理（默认 180）。 |

机密不在这里：Cloudflare API Token、连接器令牌、访问密钥与恢复密码都在 Harness 凭据库，键为 `CLOUDFLARE_API_TOKEN`、`CLOUDFLARE_TUNNEL_TOKEN`，以及本插件自己的 `dsh-remote-access/*` 记录。

行 id 是 `remote-access-panel`，**不是** `remote-access`：平台自带的 `dsh-base` bundle 已经用 `remote-access` 占用了那个位置，而 Loader 按 id 去重且**不报错**——复用那个 id 会静默顶掉平台自带的那一行，让界面的 RPC 失效。

### 随插件安装的配置 skill

装插件的同时会装一个名为 `dsh-remote-access` 的**运行时 skill**（通过 `ctx.skills.register` 注册，禁用插件即移除，不会往你的 skills 目录写任何文件）。在新对话里说一句"配置远程访问"就会触发它，模型会带着你走那条固定流水线：它**总是先问**你域名、主机名、模式和配置方式，而不是替你假设；它绝不自己发明主机名，也绝不代你运行 `cloudflared tunnel login`。

它的正文**分别覆盖 Windows / macOS / Linux**（安装命令、`%USERPROFILE%\.cloudflared` 与 `~/.cloudflared`、`$env:DSH_HOME` 与 `$DSH_HOME`），写明四种凭据来源的真实参数与恢复顺序，末尾还有一张针对真实会遇到的故障表：信任栅栏 403、`no active Cloudflare zone`、插件旧代码、过期的一次性链接，以及 100 MB 上传上限。

面板本身不放教程：面板显示状态并执行操作，说明交给 skill。

## 安全模型

### 四种凭据来源

| 来源 | 是什么 | 有效期 | 撤销 |
|---|---|---|---|
| **入口链接** | 平台每次进程生成的启动令牌，一次性换成平台 Cookie。首次配对同时写入一条设备记录。 | 链接随进程失效；记录 **30 天**，与平台 Cookie 同寿命。 | 记录可按设备撤销。平台 Cookie 本身只能**整体**撤销。 |
| **一次性配对码** | 8 位字符，字母表不含 `0`/`O`/`1`/`I`/`L`，只能从已授权会话生成，有速率限制。二维码里编码的是带上该码的网址。 | **10 分钟、只能用一次。** 它携带新设备记录拿到的有效期：永不过期 / 30 / 90 / 365 天 / 自定义日期。 | 使用即作废；它写下的那条记录仍可撤销。 |
| **访问密钥** | 有名字的密钥 `dra_…`，只显示一次，本机只存 sha256 指纹；在 `POST /remote-access/token` 兑换。 | 密钥本身是长期存储的凭据；它换出的链接是 **15 分钟、一次性**。 | 每把密钥可单独撤销或重置。 |
| **密码**（可选，fail-closed） | 挑战-应答：PBKDF2-SHA256、600,000 次迭代，再对一次性 nonce 做 HMAC，因此密码不过网。 | 一次性链接**最多 15 分钟**；页面关闭时的 beacon 会尽力提前作废它。 | 移除密码（同时撤销未用的解锁票据）。 |

### 诚实的边界

- **按设备撤销只覆盖插件签发的凭据。** 平台的浏览器 Cookie 无法按设备撤销——只有 **撤销全部已配对浏览器会话** 这一次全撤，它删除平台的会话记录，并在下次重启后落地。
- **插件不能签发平台令牌。** 临时令牌是插件凭据，用来换一条平台入口链接；Cookie 仍然由平台签发。
- **没有滑动续期。** 没有任何隐藏续期去延长任何凭据：面板显示什么，就什么时候到期。使用设备凭据只会刷新它的"最近使用"与客户端 IP。
- **没有密码就没有恢复面。** 未设置密码时，恢复页什么都不渲染，公网表面保持沉默：未认证访问域名收到平台原本的 401，`/remote-access/unlock` 返回 404。
- **Cloudflare Access 是可选的，且不由插件强制。** 面板只报告该域名前面是否挂了 Access 应用。开启后，它排在该域名上的一切之前，包括配对码页面与密码页面。
- **面板的每次调用都由平台栅栏鉴权。** 每个面板请求都先调用 `ctx.connection.requestRejection(req)`，在读取任何请求体之前返回它的判定；配对码、访问密钥、密码这三道门自己鉴权，因为它们必须恰好在平台凭据失效时可用。
- **`DSH_*` 变量属于启动器环境。** 在你启动 dsh 的地方 export；`.env` 文件里出现任何 `DSH_*` 条目都会让启动直接抛错。
- **隧道本身是公网可达的。** 谁知道域名谁就能连上这台 Harness，所以上面这些凭据就是挡在界面之前的东西。

## 已知限制

- **一个监听只能绑一个地址。** 回环、局域网字面量和隧道无法同时生效：绑定局域网地址会顶掉回环监听，`http://127.0.0.1:3080` 不再响应，桌面端也必须改用新地址。
- **局域网模式没有设备管理。** 平台的启动令牌随进程失效，所以那个模式只显示入口链接、二维码和退回回环的按钮。
- **cloudflared 子进程只在本 Harness 进程运行期间被管理。** 在面板外启动的隧道会被显示为"未配置"，而不会被接管。
- **活动列表只知道心跳看到过什么。** 它记录的是"插件已安装、心跳可达主机"期间加载过界面的设备；它是记录，不是授权依据。
- **快速隧道每次启动都会换域名**，所以每次都要重新信任，设备也要重新配对。
- **窄屏微调是纯 CSS**，且在页面加载时决定，所以桌面窗口在加载后再缩小到手机宽度，会保留桌面尺寸直到刷新。
- **审批卡片等交互都是平台自带界面**，本插件不添加手机专属交互。
